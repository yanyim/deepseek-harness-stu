# 死法二:协议太厚 → 用不到的设计堆积、臃肿失控

**目标**:协议可以有厚度,但厚度不许变成使用者的门槛,也不许堆进内核。

**病理**:内核承载领域功能 → 每个新功能都要过内核 → 必然膨胀;
契约全量必实现 → 最小使用者被吓退 → 有人为省事抄薄一份 → 分叉。

**三个思路,按「厚度去哪了」分**:

| 文件 | 思路 | 挡住什么 | 对照 dsh |
|---|---|---|---|
| (展品=`../stage/kernel.ts`) | 内核无领域知识,协议分片 | 厚度堆进内核:60 个独立小 seam 各自演化,换掉一个不惊动别人 | Cordis 内核仅 5 概念;llm 变厚不影响 fs |
| `progressive-contract.ts` | 渐进式契约:唯一必实现 | 契约门槛:`LlmAdapter` 1092 行协议只有 1 个抽象方法,其余默认实现 | `packages/llm/llm/src/index.ts:193` |
| `interception-by-event.ts` | 拦截走事件(waterfall) | 拦截需求变成协议参数:加参数=改协议=全体实现方跟着动;加监听器=局部行为 | `agent/pre-step`、`llm/stream`、`tools/*` 瀑布事件 |

**行为锁定**:`death-2.test.ts` —— 只实现 `stream()` 即可工作、缺省能力有默认值、
未实现/未注册明确报错、waterfall 观察/改写/否决三姿态、卸载即复原。
内核本身的可靠性(逆序撤销、嵌套、服务替换)锁定在 `../stage/stage.test.ts`。
